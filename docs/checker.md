# 检查器 hhsh 说明

`hhsh` 是好好说话附带的命令行检查器，用 Go 写成，有四个子命令：`scan` 做零容忍扫描，`lint` 找腔调候选，`check` 对照原文和改稿，`rules` 列出规则表。它只看字面，命中都是候选，改不改由人判断。

## 运行方式

需要 Go 1.22 及以上，在仓库根目录运行 `go run ./cmd/hhsh <子命令> [参数] 文件...`，或者先编译 `go build -o ~/bin/hhsh ./cmd/hhsh`。`hhsh version` 显示版本号，和规则表 `zh.json` 里的 `version` 一致。

规则表 `lexicon/zh.json` 在编译时嵌进二进制，改了规则表要重新编译，`go run` 每次都会重编。仓库里的 `bin/` 不进版本库，里面的旧二进制可能落后于源码，用之前自己编一次。`scan` 和 `lint` 可以一次给多个文件，不给文件或文件名写 `-` 时读标准输入；`check` 必须给两个文件，其中一个可以是 `-`。

## scan：零容忍扫描

用法是 `hhsh scan [-json] [-strict] [-skip-quoted] [文件...]`。查五项：中文里的半角逗号、句号、分号、冒号；元话语；机械编号和量词标题；“不是 X 而是 Y”及其变体超过两处；第一个 `#` 标题里的破折号。代码块、行内代码和链接不参与扫描。

- `-json`：每个文件输出一个 JSON 对象，带 `clean` 字段，五项都过时为 `true`。
- `-strict`：有半角标点时退出码为 1，其余四项不影响退出码。
- `-skip-quoted`：不报中文引号“”里的元话语、编号和“不是 X 而是 Y”，半角标点照报。

`go run ./cmd/hhsh scan 样稿.md` 的输出：

```

  中文里的半角标点：2 处（必须清零，代码、英文、千分位、网址除外，要处理）
    第7行 [半角标点] “,”  在当今数字化办公的时代,打印依然扮演着至关重要的角色
    第7行 [半角标点] “,”  货，双面打印速度提升 40%,每月耗材预计节省 600 元
  元话语：1 处（删掉或换成具体判断，要处理）

    第3行 [量词标题] “三板斧”  ## 三板斧：选型、试用、上线
```

## lint：腔调候选和排版信号

用法是 `hhsh lint [-json] [-min 1] [-skip-quoted] [-rules 文件] [文件...]`。用规则表逐条匹配，再统计排版和句长。

- `-json`：输出全部命中和统计，不受 `-min`、`-skip-quoted` 影响。
- `-min N`：只显示权重不低于 N 的命中，N 取 1 到 3，默认 1。
- `-skip-quoted`：不显示引号里的命中，引号认“”「」『』，只在同一行内配对。腔调指数照算。
- `-rules 文件`：用另一份规则表整个替换内置表，用来试新规则。

`go run ./cmd/hhsh lint 样稿.md` 的输出：

```
样稿.md：167 个汉字，腔调指数 119.8（每千字加权命中，0 最好）
命中：
  第5行 [开场铺垫·3] “值得注意的是” → 删掉提示语，直接说后面的内容（保留：后面确实是风险或例外时，可改成“要注意”）
      值得注意的是，这次升级不是简单地换一
  第5行 [句式模板·2] “不是简单地换一台机器，而是” → 多数直接说成立的那一半；两边确有区别时保留（保留：两边是不同的具体事实）
      值得注意的是，这次升级不是简单地换一台机器，而是一次办公体验的全面重塑。
  第7行 [开场铺垫·3] “在当今数字化办公的时代” → 删掉，或换成具体时间
      在当今数字化办公的时代,打印依然扮演着至关重要
  第7行 [空泛拔高·3] “扮演着至关重要的角色” → 直接说它做什么
      字化办公的时代,打印依然扮演着至关重要的角色。新打印机 11 月 4
  第7行 [黑话·3] “赋能” → 写清谁帮谁做成什么，例如“客服用新系统查订单更快了”
      计节省 600 元，有效赋能各部门的日常工作。
  第11行 [收尾套话·3] “携手共进” → 删掉口号
      让我们携手共进，共同打造更加高效的办公
  第11行 [收尾套话·3] “共同打造更加高效的办公环境” → 删掉口号
      让我们携手共进，共同打造更加高效的办公环境！
排版信号：标题 2 · 破折号 1 · 感叹号 1 · 半角标点 1
节奏：8 句，平均 21 字，句长变异系数 0.45
提示：命中只是候选，先判断它在这里是不是术语、引语或作者本来的意思。
```

- **腔调指数**：命中权重之和乘 1000 再除以汉字数。改稿前后对比才有意义，短文本里一处命中就能把指数推过一百。
- **命中行**：方括号里是类别和权重，箭头后是改法，“保留”后是该留的情形，下一行是上下文。两条规则命中同一段字时，只报权重高的，权重相同报匹配更长的。
- **排版信号**：标题、加粗、列表行、表情、破折号、感叹号、半角标点、四字格连用（三个及以上四字短语连用）、超长句（超过 60 个汉字）、“的”字堆叠句（一句里四个以上“的”），有才显示。
- **排比、节奏、连接词**：一句里三个以上分句用同样两个字开头时列为排比；至少 8 句才算句长变异系数，低于 0.35 注明“句子长短太均匀”；200 字以上、每千字超过 25 个“此外、然而、因此”这类词时提示偏多。

## check：原文和改稿对照

用法是 `hhsh check [-json] [-rules 文件] 原文 改稿`。`go run ./cmd/hhsh check 样稿.md 改稿.md` 的输出：

```
保护项核对（数字、日期、时间、版本、代码、链接、书名、英文名）：
  可能丢失 1 项：数字“600 元”
  （中文数字改写成阿拉伯数字也会出现在这里，逐项确认）
  原文没有、改稿新增 1 项：数字“3 天”（确认不是编出来的）
改动：编辑距离占 78%；篇幅 167 → 79 个汉字（47%）
腔调指数：119.8 → 0.0；原文命中 7 处，改稿残留 0 处，新增 0 处
```

保护项指代码、链接、书名、日期、时间、版本号、数字（带常见单位）、中文数字和英文词。比较前会抹平空格、全半角和写法差异，“1.2 万”和“12000”、“百分之四十”和“40%”算同一个。样例里“600 元”写成了“600 多元”，报丢失；“3 天内装到各楼层”是改稿编出来的，报新增。这两处都是真问题。

“改动”一行给编辑距离占比和篇幅比，本来就自然的文字改动率应该接近零。最后一行比较前后的腔调指数，“残留”是原文就有、改稿还在的命中，“新增”是改稿新长出来的，两类都会逐条列出。

## rules：查看规则表

用法是 `hhsh rules [-cat 类别]`，`-cat` 用英文键名。它只列内置规则表，不读 `-rules`。`go run ./cmd/hhsh rules -cat chat` 的输出先是一行总数，后面是这样的规则行（节选）：

```
## 聊天腔（chat）
  [3] ch-haowenti      (非常|很|真)?好的问题|好问题[！!] → 删掉，直接回答
  [2] ch-shuodedui     你(说|问)得(很|非常|太)?(对|好) → 删掉
```

每行依次是权重、规则 ID、正则、改法，有保留条件时末尾加“；保留：……”。

## 退出码

| 退出码 | 什么时候 |
|---|---|
| 0 | 正常跑完。`lint`、`check` 不管命中多少都是 0，`scan` 不带 `-strict` 也是 0；`-h` 也返回 0 |
| 1 | `scan -strict` 发现半角标点；或者运行出错：文件打不开、`check` 没给两个文件、`-rules` 的规则表解析失败 |
| 2 | 没给子命令、子命令拼错，或者参数不认识 |

用 `go run` 时，程序的非零退出码会被统一换成 1，并多打一行 `exit status 2` 之类的提示。CI 里要区分退出码，先编译再跑二进制。

## 规则表 zh.json

`lexicon/zh.json` 顶层有四个字段：`version`（跟着发版改）、`note`（说明）、`categories`（类别键名到中文名）、`rules`（规则数组）。写这份说明时有 199 条，权重 3 的 56 条、2 的 100 条、1 的 43 条，最新数字看 `hhsh rules` 第一行。

| 字段 | 含义 | 要求 |
|---|---|---|
| `id` | 类别前缀加拼音，如 `jg-funeng` | 必填，全表唯一 |
| `cat` | 类别键名 | 必须在 `categories` 里定义过 |
| `w` | 3 在中文里几乎总是腔调，2 多数情况是腔调，1 看用途 | 1 到 3 |
| `re` | Go 正则，RE2 语法，不支持前后断言和反向引用 | 必填，能编译，不能匹配空串 |
| `hint` | 改法，显示在箭头后面 | 测试要求非空 |
| `keep` | 应当保留的情形 | 可选 |

类别键名和 ID 前缀：工具痕迹 `trace`（tc）、开场铺垫 `opener`（op）、收尾套话 `closer`（cl）、聊天腔 `chat`（ch）、黑话 `jargon`（jg）、宣传夸饰 `hype`（hp）、空泛拔高 `lofty`（lf）、句式模板 `template`（tp）、翻译腔 `transl`（tr）、文艺腔 `literary`（lt）、网感硬凹 `webslang`（ws）、工程师腔 `engineer`（en）、服务腔 `service`（sv）。`trace` 类对原文匹配，能查到链接里的参数；其余类别对去掉代码和链接后的文字匹配。

**keep 怎么写。** `keep` 是写给人看的，程序不拿它做判断，只原样显示在 `lint` 和 `rules` 的输出里。写一个具体的场合加一个例子，让人一眼判断眼前这处该不该留，比如“闭环控制、闭环反馈等技术含义”“存储系统里写盘的本义”；“视情况保留”“正式场合可用”这类写法读的人照样判断不了。一个词在某个行当里有确切含义，或者在某种文体里是惯例（公文、学术、致辞），就该写 `keep`；写不出具体的保留场合，这条规则多半可以给权重 3。

## 加一条规则并补测试

以“水位”为例。它在监控和容量规划里是术语，在“把团队的情绪水位拉回来”这类汇报里是工程师腔。

**先用临时规则表试。** `-rules` 会整个替换内置表，所以要复制完整的一份再加规则：`cp lexicon/zh.json /tmp/try.json`，编辑后跑 `go run ./cmd/hhsh lint -rules /tmp/try.json 样本.md`，样本里既要有该命中的腔调，也要有该放过的正当用法。

**写进规则表。** 放在同类规则旁边：

```json
{
  "id": "en-shuiwei",
  "cat": "engineer",
  "w": 2,
  "re": "水位",
  "hint": "说具体的量：库存还剩多少、队列积压多少",
  "keep": "监控和容量规划里有具体阈值的水位线（如“磁盘水位超过 80% 告警”）"
}
```

**补测试。** 在 `internal/lint/lint_test.go` 的 `TestCatchesTypicalPatterns` 里加一行例句到规则 ID 的映射，例如 `"这周把团队的情绪水位拉回来。": "en-shuiwei",`。例句自己编，不能取自评测用例。同一个文件里的 `TestNaturalTextIsQuiet` 要求几段自然文字没有权重 2 以上的命中，正则太宽会在这里报错。

然后跑 `go test ./...`：`lexicon` 包的测试会查 ID 重复、类别未定义、权重越界、正则编译失败和匹配空串。最后看 [references/patterns.md](../references/patterns.md) 里有没有对应的症状，没有就按 [contributing.md](contributing.md) 的要求一起补。

## 在 CI 里用

下面的 GitHub Actions 工作流放进本仓库的 `.github/workflows/`，改了 Markdown 的 PR 会跑：半角标点不清零就失败，其余四项有命中也失败，腔调候选只打印出来给评审参考。

```yaml
name: hhsh
on:
  pull_request:
    paths: ["**.md"]
jobs:
  zh-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: "1.22"
      - run: go build -o hhsh ./cmd/hhsh
      - name: half-width punctuation
        run: ./hhsh scan -strict -skip-quoted README.md docs/guide.md docs/checker.md
      - name: all five scan items
        run: ./hhsh scan -json -skip-quoted README.md docs/guide.md docs/checker.md | jq -s -e 'map(.clean) | all'
      - name: tone candidates (report only)
        run: ./hhsh lint -min 2 -skip-quoted README.md docs/guide.md docs/checker.md
```

`scan -json` 每个文件输出一个对象，`jq -s` 把它们收成数组，有一个不干净 `jq -e` 就返回 1。在别的仓库里用，先用 `actions/checkout` 把本仓库检出到子目录，再在子目录里编译；模块名是 `haohao-shuohua`，不能直接 `go install`。

## 局限

- **只看字面。** 规则是正则，分不出术语和装饰、引用和本意。`keep` 只是提示，不会自动放行。
- **check 不认情态词。** 样例里“预计节省”改成了“能省下”，强弱变了，`check` 没报，它报的是数字写法变了。“计划、预计、力争、可能”要人工对，人名、机构名、否定和条件也不在核对范围内。
- **两处半角标点口径不同。** `scan` 查汉字或全角标点旁边的半角逗号、句号、分号、冒号；`lint` 的排版信号查汉字后紧跟的半角逗号、分号、冒号、叹号、问号。样例里两边是 2 和 1，以 `scan` 为准。
- **编号和引号靠启发式。** 不带 `#` 的行，只有 20 字以内、不以标点结尾、以“一、”或“第 N 章”开头的才算标题；标题破折号只查第一个 `#` 标题；引号只在同一行内配对。
- **不判断是不是 AI 写的。** 检查器帮人少漏，不替人判断，也不负责降低 AI 检测率。
