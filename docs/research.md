# 调研笔记：中文去 AI 味的开源 skill

调研时间：2026-10-21。GitHub 上没有名为 haohao-shuohua 的现成项目（同名的只有一个社交媒体账号），所以本项目以下面几个开源 skill 为基础重新设计，并把它们作为评测对照组。

## 结论先行

1. **成熟项目已经从“词表”走向“原则”。** 说人话（shuorenhua）早期有 210 多条中文短语规则、25 类结构反模式、分场景规则包，参考资料一度超过 120 KB；到 v2.5 精简成不到 10 KB的 SKILL.md 加两份参考。它自己的三方案对比里，旧的长规则在 24 题里一次都没被单独选为最好，精简后的新规则被选 11 次，简单提示 5 次。规则越长，模型越容易机械执行、越容易改过头，token 也贵得多。
2. **保真是硬门槛。** 说人话把“信息保真”和“遵守任务”设成发布硬门槛，正常文本误改率要求低于 10%（实际 0/58）。这条值得照搬：去味改丢一个数字，整篇就不能用。
3. **太保守也有代价。** 说人话 v2.6 默认不处理宣传口气和黑话，只在用户明确说“别吹”时降夸饰；它的验证记录里承认，带“打造”“赋能”“闭环”的宣传句在默认模式下原样返回，长文黑话清理偏少是已知缺口。123 题里质量判为“更好”的只有 19 题，102 题“不变”。
4. **另一头的风险是“假人味”。** 部分 skill 鼓励“注入个性”“加人味”，容易让模型往文字里塞口语词、网络梗和情绪，变成另一种一眼就能认出的腔调。
5. **因此本项目的取舍是：** 保真门槛照说人话的标准；默认就清黑话、宣传腔、模板结构和工程师腔，但只用原文给出的信息替换；把“语体守恒”和“不长新腔调”写成和保真同等重要的原则；SKILL.md 保持精简，细节放在按需读取的参考资料里；另配一个确定性的检查器，帮模型核对保护项和残留。

## 说人话 shuorenhua（MrGeDiao，MIT，v2.6.0，约 1.8k★）

- **定位**：编辑，不是检测器；不输出“AI 含量”。口号是“先保信息，再谈风格”。
- **默认动作**很窄：删纯招呼、致谢、没内容的预告和口头填充；删只提示写法的成分；删完整重复；简化名词化和累赘功能词；删无依据的读者身份认证（“你已经超过大多数人”）。其余默认保留，包括宣传口气和修饰词。
- **编辑范围**：structural / bounded / in-place 三档；中文公开长文约 1000 字以上默认 bounded（不删整句、不并句）。
- **无源论断**：“研究表明”这类没有来源的说法，默认保留归属并在正文外提示缺来源，不删也不编来源。
- **只标问题模式**、**写平实模式**（v2.6，用户说“别吹”时才降夸饰、删口号）。
- **评测**：123 条用例（58 条正常文本），信息保真 / 遵守任务 / 编辑质量分开判；双模型盲改写、交叉判分；判官先做参考案例校准；发布门槛事前写死。脚本里有保护片段粗核（数字、版本、路径、代码）和句长变异系数、连接词密度、名词化命中等硬指标。
- **可借鉴**：保真门槛、对照组误改率、保护片段核对、“命中词表不构成删除理由”、精简规则。
- **短板**：默认太保守，黑话和宣传腔清得少；不管从零写作。

## Humanizer-zh（op7418，MIT，3k★ 级别）

- **定位**：编辑已有中文文章，去掉空话、重复和模板化表达，保留事实、确定程度和作者声音。英文 humanizer 的中文版，2026-09 大改的动机是“文章改顺了，意思却变了”，整份规则围绕保真重写。
- **规则**：31 个检查点、6 类；前 5 类沿用英文版骨架，中文原生的只有第 6 类（“的”字层叠、“进行＋动词”、被字句、四字词排比、“随着……的发展”开头、套话收尾）。每条都带“改前/改后/保留”三段示例。
- **流程**：通读 → 只改确实存在的问题 → 对照原文查新增、遗漏、强化 → 通读润色；专门盘点“可能、据称、超过、仅、正在、计划”这类承载确定程度的词。
- **评测**：18 条短例 + 1 个文件样例，旧版对新版自我对照，没有空白基线和盲评。
- **可借鉴**：规则自带“保留”反例；保真词盘点；允许零修改；待改文字只当材料。
- **短板**：408 行单文件，常驻成本高；中文本土腔调覆盖有限；不管从零写作。

## qu-ai-wei（LifelongLazyLearner，MIT，v0.9.1）

- **定位**：去除简体中文 AI 写作痕迹，偏自媒体长文。
- **流程很重**：先过“门检”（拦凭证、判断授权与语体、用途不明先问），信息账本加论证图、先全局后局部，输出终稿后还要附“打磨报告”；29 个模式各带证据等级和来源。
- **评测**：20 个回归案例、242 条断言（只守硬边界：关键事实在不在、升级措辞有没有出现）；盲评机制完整但仓库没有公布结果。
- **可借鉴**：仲裁顺序（事实与原意 > 用途与语体 > 作者声口 > 自然表达 > 原格式）；否定和排除不升级（“不能归因于不够努力”不能写成“与努力无关”）；不为了打破三连删掉独立的例子；“自然不等于口语化”。
- **短板**：流程和报告太重（SKILL.md 加参考约 777 行）；个别示例和规则自相矛盾；回归断言一刀切禁止“不是……而是……”。

## speak-human-tw（Raymondhou0917，MIT，v1.4，繁体）

- **定位**：繁体中文（台湾）的去 AI 味校对，顺带改中国用语和半形标点。默认两轮：先列完整修改清单，用户勾选后才改。
- **规则**：38 种痕迹、5 大类，含硬阈值（破折号每 300–500 字最多一次、“不是 A 而是 B”整篇最多一次）。
- **评测**：42 条合成用例，成对维护“该改必中”和“不可误杀”；判分加“不换汤”（删“標誌著”补“象徵著”算失败）；v1.4 用 Codex 改写、Claude 判分，命中 96%、误杀 0。
- **可借鉴**：“不换汤”判据；数字精度和立场强度不漂移（“約 42%”不能变“超過四成”，“我反對”不能稀释）；工具痕迹（`utm_source=chatgpt.com`、`turn0search` 占位码）作为一眼铁证优先清；“人味是作者的，不是你的”，缺信息留占位不编。
- **短板**：自己的示例违反自己的保真规则（改后版本加了原文没有的数字和经历）；强制两轮对日常使用摩擦大；只面向繁体。

## renhua（huangserva，无许可证）

- **定位**：把 AI / 技术自媒体稿改成作者本人的口吻，高度个人化（规则里有作者本人的“永久规则”）。单文件约 1190 行。
- **可借鉴**：“把最抢眼的词换成最平的说法，信息没少，那个词就是在表演”这条母规则；先语境、再句子、最后词汇的顺序；压缩腔（动词砍成单字、虚词被省掉的电报体）这一类别别处很少覆盖。
- **短板**：没有许可证，只能借鉴思路；个人偏好写成通用规则；没有评测。

## de-ai-flavor-skill（ren644，无许可证）

- **定位**：写作时自动遵守的风格约束，不是改稿流程。支持导入作者 1–3 篇文章提取风格指纹（句长、口语化、人称、段落节奏、连接方式、情绪温度、标点习惯）。
- **可借鉴**：给不支持 skill 的平台准备一份约 20 行的精简版；“什么都对但什么都没说”这条自检。
- **短板**：没有保真规则，没有示例和评测。

## humanizer（blader，MIT，英文）与 stop-slop（hardikpandya，MIT，英文）

- humanizer 把维基百科 WikiProject AI Cleanup 总结的 AI 写作痕迹做成 skill，是 Humanizer-zh 的上游；stop-slop 是一份很短的英文冗余表达规则。两者对中文的直接价值有限，主要是分类思路。

## 吸收了什么、避开了什么

| 吸收 | 来自 |
|---|---|
| 保真门槛、对照组误改率、保护片段逐字核对 | 说人话 |
| 规则自带“保留”反例；保真词盘点 | Humanizer-zh |
| 否定不扩大；不为破三连删独立例子；“自然不等于口语化” | qu-ai-wei |
| “不换汤”判据；精度与强度不漂移；工具痕迹；缺信息留占位 | speak-human-tw |
| “最抢眼的词换成最平的说法”试法；压缩腔 | renhua（只借思路） |
| 精简版供无 skill 平台使用 | de-ai-flavor-skill（只借思路） |

| 避开 | 原因 |
|---|---|
| 长词表常驻上下文 | 说人话自己的对比里长规则效果最差，token 也贵十倍 |
| 强制两轮确认、强制附报告 | 日常改一段消息不该这么重；需要时用户可以要求“只标问题” |
| 硬阈值（“整篇最多一次”） | 机械执行会误伤有意的对比；改用“看这句话在干什么” |
| 鼓励“加人味” | 会长出假口语、编造细节，变成另一种 AI 味 |
| 默认不碰黑话和宣传腔 | 说人话已知缺口，用户要的恰恰是这部分 |
