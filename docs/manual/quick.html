1它做三件事

改稿（默认）

把 AI 味重的中文改成能直接发出去的版本。本来就自然的文字，原样交回并告诉你不用改。

从零写

替你起草消息、邮件、通知、文章时，一开始就按这套标准写，语气按你的要求来。

只标问题

不动原文，引用原句，指出哪里有腔调、该怎么改。适合想自己动手的时候。

3底线和改法

冲突时按这个顺序让路：保真 > 场合 > 力度 > 风格。数字、术语原词、因果方向、承诺、条件、否定，以及“计划 / 预计 / 力争 / 可能”的强弱，一条都不动；原文没有的原因、例子、承诺不补，缺的写进给你的提醒。

先看全篇，从含义出发。读懂每段在讲什么，再整体改，最后才落到句子；多余的句子和段落可以删。逐句翻译式的改写，顺不出好文章。

手别太痒。没毛病的句子原样留着，每处改动都说得出治的是什么毛病。去 AI 味也不等于口语化，不会往文字里塞“说白了”、网络梗和表情。

4怎么说

直接把文字贴进来，说清用途就行。几种常见说法：

把这段去掉 AI 味，保留信息和我的口气：……
这是 Codex 写的进度汇报，改成正常中文，我要转给组里：……
帮我写一条工作消息，通知下周三晚上数据库迁移，时间 21:00–23:00，期间订单服务只读。
这份 PRD 的背景和目标是 AI 起的稿，评审前帮我改实一点，结构别动：……
只标问题，不改写：……

可以叠加的要求（都比默认规则优先）

只改措辞保留结构可以大改别大改别吹保留小红书语气要能念出来更正式一点控制在 100 字以内记住我的风格

5它会清掉什么、留下什么

会清掉举例
开场铺垫、结尾升华在当今……的时代；综上所述；希望对你有帮助
公式句、翻案句不是……而是……；看似……实则……（全文最多两处）
结构排比三板斧、五个维度、凑满三个的名词串、文章里的“一、二、三”
黑话、夸饰、元话语赋能、闭环；重磅、极致；值得深思、不难看出

本行术语链路追踪、闭环控制、兜底策略、统计学上的“显著”

藏在空话里的事实“XX，一座……的城市”里的地名

6你会拿到什么

  • 默认只给改好的正文，能直接复制去用，前面不加“以下是改写后的版本”。
  • 必要时正文后最多三行说明：拿不准的地方、建议删但没删的句子、缺来源的说法，或者日期和星期对不上这类事实疑点（正文照原样保留，提醒你确认）。
  • 本来就自然的文字：原文一字不改交回，加一两句为什么不用改。
  • 只标问题：引用原句、说明问题和改法，不交全文替换稿。
改到什么程度默认标准档：句子和段落改到位，多余的照删，不调章节顺序。说“大改”可以重组段落、调章节；说“别大改”只换词，该删的整段列出来给你定。场合也会影响尺度：对外公告说清说准，客服和致辞的客套是功能件，私人消息才是口语的主场。

7检查器 hhsh（可选）

Go 写的小工具，帮你少漏，不替你判断。需要 Go 1.22 及以上，在 skill 目录里运行：

go run ./cmd/hhsh lint 稿子.md            # 腔调候选、排版信号、句长节奏
go run ./cmd/hhsh check 原文.md 改稿.md    # 数字/日期/代码有没有丢或凭空多出；残留和新增腔调
go run ./cmd/hhsh scan 稿子.md            # 四项零容忍：中文里的半角标点、元话语、机械编号、“不是 X 而是 Y”超过两处

命中只是候选：同一个词在技术文档里可能是术语，在宣传稿里才是腔调。它也不负责“降低 AI 检测率”。

9常见问题

改完能通过 AI 检测吗？

不保证，也不以此为目标。它在意的是读者读起来自然、信息完整。

为什么有时原样返回？

原文已经是人话了。硬改只会把口语改成书面语、把细节改成概括。

会替我补内容吗？

不会。觉得缺什么，会在正文后提一句，由你决定加不加。

“闭环”“兜底”是我们行业的术语？

照用。“闭环控制”“兜底策略”是术语，“形成完整闭环”“稳稳兜住”才是腔调。

详细的规则、分场景尺度、改写对照和每一轮评测记录都在仓库里：SKILL.md、references/、evals/、docs/guide.md、docs/iterations.md。
