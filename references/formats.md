同一段话贴到不同的地方，能用的格式不一样。按渠道查：能用什么、不能用什么、篇幅习惯、贴出去会露馅的东西，以及用户给了字数时怎么守。

## 动手前先看显示端

- **渲染不渲染 Markdown**：微信、短信、多数群公告、商店的更新说明、按纯文本显示的邮件都不渲染，星号和井号会原样露出来。拿不准就按不渲染写。
- **读者怎么读**：扫一眼、细读还是听。扫读的给分行，细读的给段落，听的只给能念的字。
- **用户的要求优先**：用户说了“保留原来的分条”“要能直接贴进群里”，照他说的来。

## 贴出去会露馅的痕迹

| 痕迹 | 怎么处理 |
|---|---|
| `**加粗**`、`__加粗__` | 删掉符号；要强调，就把要紧的词挪到句首 |
| `#`、`##` 开头的标题 | 删掉；要分块用空行 |
| `- `、`* ` 开头的列表符 | 改成换行；确实要编号时用纯文本的 `1.`、`2.` |
| `>` 引用、`---` 分割线、反引号 | 删掉 |
| `[文字](链接)` | 写成“文字”加完整链接，链接单独一行 |
| Markdown 表格的竖线 | 改成分行文字，或者交给用户一份表格文件 |
| 中文里夹着半角逗号、句号、冒号、括号 | 换成全角；代码、英文、网址、千分位除外 |
| 中文引号和直引号混用 | 中文正文统一用“”和‘’ |
| 中英文之间空格时有时无 | 跟全稿统一，有就都有 |
| 复制后自动编号全变成 `1.` | 手动重排或改成换行 |
| `[你的名字]` 这类没填的占位 | 提醒作者补上 |

## 即时消息（微信、企业 IM）

- **能用**：换行分开几件事；企业 IM 里要谁做事就 @ 谁；链接单独一行；熟人私聊、作者本来就这么说话时，可以有一两个表情。
- **不能用**：标题、加粗、Markdown 列表符、分割线；“【重要】【必看】”这类方括号标签叠用；多级编号。
- **篇幅**：一屏以内，第一句就是要对方做什么、什么时候。超过一屏的，拆成两条，或者写进文档贴链接。
- **会露馅的**：有的企业 IM 在电脑端渲染 Markdown，手机端却露出星号；从文档复制过来的缩进和项目符号。
- **给了字数**：用户说“一句话”“简短点”，只留动作、时间、对象和条件。

## 短信

- **能用**：纯文字。企业群发短信开头的【签名】是平台要求，留着，只留一个。
- **不能用**：表情（有的手机显示成方块）、Markdown、多段空行排版。
- **篇幅**：含中文的短信一条 70 字以内，超了会拆成几条，有的手机还会分开到达。验证码、取件码、时间、地点放在前半截。
- **会露馅的**：星号、半角标点、签名重复出现两次、链接被换行切断。
- **给了字数**：签名、标点和空格都算字数，交付时报一下实际字数。

## 群公告

- **能用**：第一行用一句话说清是什么事（不加符号）；几项并列的要求用纯文本的 `1.`、`2.`分行；时间、地点、联系人各占一行。
- **不能用**：Markdown 加粗和标题符号；“【重要通知】”“温馨提示”叠用；成排的表情。
- **篇幅**：手机上一屏到一屏半。更长的内容放文档，公告里贴链接，写清要大家做什么。
- **会露馅的**：星号、井号、从文档复制来的多级缩进。
- **给了字数**：公告栏有上限时，先砍客套和重复，再砍背景；时间、地点、要求、联系人不砍。

## 邮件

- **能用**：称呼、分段的正文、一句结尾、落款（姓名、部门、联系方式）；要对方逐项回复的三件以上事项，用数字编号分行；附件在正文里点名说是什么。
- **主题行**：写具体事项，最好带时间，比如“周四的评审改到下午两点”，不写“关于相关事宜的沟通”。
- **不能用**：Markdown 符号（不少客户端按纯文本显示）、表情、正文里的大标题、整段加粗、五颜六色的字。
- **篇幅**：一屏读完要点。长材料放附件或文档，正文写结论和要对方做的事。
- **会露馅的**：星号、半角全角混排、签名档出现两遍、转发时留下的“以下是邮件正文”。
- **给了字数**：称呼和落款不压；先压正文里的铺垫和重复。

## Markdown 文档

README、知识库、内部 wiki 这类会渲染的地方。

- **能用**：标题层级（一般到三级）、列表、表格、代码块、链接；加粗只给术语第一次出现或警告。
- **不能用**：每段都加粗；标题下面紧跟一句复述标题的引导语；拿表情当列表符号；超过两层的嵌套列表。
- **篇幅**：一节说一件事，一节长到要翻好几屏就拆。
- **会露馅的**：井号后面漏了空格（`##标题`）导致不渲染；列表前缺空行；表格各行列数对不上；命令没放进代码块，引号被编辑器换成了中文引号。
- **给了字数**：代码、命令和 Markdown 符号不算字数，只算正文。

## PRD 和技术文档

结构本身是内容，细则见 SKILL.md 的“PRD、技术方案这类文档”一节，这里只补格式上的几条。

- **能用**：编号小节（1.1、1.2）、表格、代码块、接口定义、需求强度标记（P0、P1）、Given/When/Then。
- **不能用**：加粗的宣传结论、表情、文章式的量词标题。
- **篇幅**：跟着团队的模板走。
- **会露馅的**：配置项和字段名没加代码格式，被当成普通词改掉；从聊天里复制来的口语和表情。
- **给了字数**：先砍背景和重复说明；验收标准、待确认项、风险和缓解不砍。

## 新闻稿

- **电头**：消息稿第一段开头的“本报讯（记者 王静）”或“X 月 X 日电”是格式，单独留在导语最前面，不并进句子，也不改成“近日”。
- **导语**：第一段一两句说清谁、什么时候、在哪里、做了什么、结果怎样，不从时代背景写起，一般不超过一百字。
- **引语**：直接引语放在中文引号里，引的是原话，不改字，要删节就用省略号。说话人第一次出现写全名和职务（“区园林所副所长张华说”），之后用姓或“他”。引语动词用“说”“表示”就够，不加“深情地”“激动地”。
- **能用**：长稿的小标题、图片说明。
- **不能用**：加粗、表情、感叹号连用；“今天”“昨天”这类见报后会变的说法，写具体日期。
- **篇幅**：消息稿多在一千字以内，按重要程度从前往后排。
- **会露馅的**：电头被并进导语；引语被改写后还留着引号。
- **给了字数**：从后往前砍，电头、导语和引语原话不砍。

## 要念出来的稿子

致辞、主持词、播客稿、视频口播都算。

- **先分清是台本还是念稿**：多人主持词、晚会流程稿是台本，“【开场】”“【抽奖】”这类环节标注和“甲：”“乙：”的分工是结构，改稿时照留，只改要念的那些话。用户说明要一份拿着直接念的稿子（提词器、单人致辞），才把段落标签和“（停顿）”“（看向嘉宾）”这类括号说明从正文拿掉，需要的提示单独列在正文后面。拿不准时照留，在提醒里问一句。
- **句子能一口气念完**：一句话到停顿处大约二十来个字，长定语拆成两句；括号里的补充念不出来，改成单独一句。
- **数字写法**：改稿时数字照原文写法，阿拉伯数字也是原文的一部分；用户要口播稿、提词器稿时才改成念法（“3～5 人”写成“三到五个人”，“%”写成“百分之”），值不变。从零写念稿时可以直接按念法写。拿不准就照原文，在提醒里问一句。
- **书名号和引号听不见**：要让听众知道是书名或原话，就在句子里交代（“这本书叫……”“他原话是……”）。
- **篇幅**：按时长估，正常语速每分钟大约两百到两百五十字。
- **会露馅的**：Markdown 标题和列表、破折号和省略号连用、念起来同音容易听岔的词。
- **给了字数或时长**：给的是时长，就换算成字数，交付时把字数和估算的时长一起报给用户。

## 应用商店更新说明

- **能用**：开头一句带点温度；几条改动分行列出，每条写成一句完整的话，说清用户能感到的变化（“搜索结果会按距离排序了”）。原文就是分条的，保留分条，不必并成段落。
- **不能用**：加粗和标题（商店按纯文本显示）；只有名词没有动作的条目（“搜索优化”）；“全面提升用户体验”这类空话。原文只有一句“修复了一些问题”，就留一句平常的说法，不编具体修复了什么。
- **篇幅**：手机上折叠前只露两三行，最要紧的改动放第一条。
- **会露馅的**：内部工单号、代号、开发术语（“重构了渲染层”）。能用原文的信息换成用户感受到的变化就换；换不出来就留着，在说明里提醒作者。
- **给了字数**：先合并同类条目，再删修饰；用户能感到的改动不删。

## 社交平台帖子

朋友圈、种草笔记、短帖。

- **能用**：口语；少量起标记作用的表情（📍地址、💰价格）；话题标签放在末尾；段落短，常换行。
- **不能用**：Markdown 标题和加粗；每行一个表情；正文里塞一串话题标签。
- **篇幅**：朋友圈几行到一屏；笔记类的开头两行决定读者点不点开，最具体的信息放前面。
- **会露馅的**：话题标签的写法各平台不同（“#话题”和“#话题#”），跟用户原文的写法走；星号；半角标点。
- **给了字数**：先砍重复的感受和堆叠的形容词；地址、价格、时间、排队情况不砍。

## PPT 和海报文案

- **能用**：每页一个意思，页标题写成一句判断（见 [titles.md](titles.md)）；要点每条一行；关键数字单独成行，方便放大。
- **不能用**：整段的长句；同一页里有的要点带句号、有的不带（要么全加，要么全不加）；为了对齐硬凑字数相同的四字短语。
- **篇幅**：一页要点不超过五六条，每条一行放得下，大约二十字以内；海报主标题十个字上下。
- **会露馅的**：从文档复制来的 Markdown 符号和自动编号；中英文标点混用；换行把一个词切在两行。
- **给了字数**：版面固定时，先换短词，再删修饰，最后合并条目；数字、产品名、日期不缩写。

## 表格里的文字

- **能用**：短语；带单位的数字；同一列用同一种句式（都用名词短语，或都用动宾短语）；表头写清单位（“金额（万元）”）。
- **不能用**：格子里写长段落；加粗和表情；空着不填让人猜，没有就写“无”。格子里是短语就不加句号。
- **篇幅**：一格一两行，说不完的写在表下的注释里。
- **会露馅的**：Markdown 表格贴到不渲染的地方，竖线和横线全露出来；数字列混进全角数字或单位，没法计算；同一列的百分号和小数位写法不统一。
- **给了字数**：限了格子的字数，就把解释挪到注释，格子里只留结论。

## 用户给了字数时

- 字数按交付正文算，标点算在内；落在要求上下一成以内算守住。
- **偏短**：回原文找被删掉的具体信息、过渡和语气，补回来；不补原文没有的东西。原文本身撑不到这个长度，就在说明里讲清楚，报出实际字数，别注水。
- **偏长**：先删套话和重复，再并句，再删次要的修饰；事实最后动，要动先问用户。
- 交付时报一句实际字数。

## 列表还是段落

先问一句：这几件事之间有没有“因为、所以、但是、于是”？有，写段落，列表会把这些关系切断；没有，彼此独立，读者要挑着看或者逐项去做，就用列表。

- **用列表**：几件并列、要扫读的事，比如材料清单、操作步骤、更新说明、会后待办、对参会人的几项要求。
- **用段落**：有因果、转折、先后推理的内容，比如解释原因、讲经过、论证、说服。
- **即时消息**：三件以内的事用短句分行，不必编号；超过三件，或者要对方逐项回复，再编号。
- **一项不成列表**，两项多半一句话就能说完。
- 列表各项的长度和句式大致一样；某一项长到三行以上，这部分多半该写成段落。
- 列表改段落时，补上项与项之间原本就有的关系词，每一项都留下；段落拆成列表时，原文的因果和转折要留在条目里，别拆丢。

即时消息里编号过于正式的例子：

改前：

```text
1. 明早九点前把报价单发我
2. 下午的会挪到三点
3. 合同模板放共享盘了
```

改后：

```text
明早九点前把报价单发我
下午的会挪到三点
合同模板放共享盘了
```

反过来，有因果的内容被拆成列表的例子：

改前：

> - 物流仓周三停电检修
> - 周三的订单周四才能发出
> - 已经通知客服准备解释话术

改后：

> 物流仓周三停电检修，当天的订单要到周四才能发出，客服那边已经通知了，让他们准备好怎么跟客户解释。
