# 腔调模式库

按“从大到小”分层。每条写：样子、为什么像 AI、怎么改、什么时候留。这里是举例，不是禁词表——换一套字做同一件事（同样的铺垫、拔高、空承诺），照样是腔调。

检查器 `hhsh` 的规则表在 `lexicon/zh.json`，和这里的分类一一对应。

## 一个通用的试法

拿不准某个词是不是腔调，把句子里最抢眼的那个词换成最平常的说法，再读一遍：意思一点没少，它就是在表演，换掉；意思变了或少了，它在干活，留下。这个试法比背词表管用，因为新说法天天有，AI 摆词的位置却总是那几处：句首、句尾、修饰语和动词的位置。

## 目录

0. 工具痕迹：一眼就能认出的残留
1. 结构层：开场、收尾、凑数、排版

4. 词汇层：黑话、夸饰、空泛拔高、元话语
5. 翻译腔与欧化

8. 造词、比喻、词不配位
9. 改过头：新长出来的腔调

**密度。** 一段里命中超过五处，逐处改救不回来，整段按原意重写；用户说了“别大改”时，把这段列进建议删改清单交给作者。

## 0. 工具痕迹

这些不是文风问题，是 AI 工具直接留下的残留，见到就清：

| 样子 | 怎么处理 |
|---|---|
| 链接里的 `utm_source=chatgpt.com` 之类参数 | 删参数，留链接本体；作者自己设的 UTM 不动 |
| `turn0search3`、`【4†source】`、`oaicite:2` 这类引用占位码 | 删掉；需要出处就换成真实来源 |
| “作为一个 AI 语言模型”“截至我的知识更新” | 删掉 |
| `[你的姓名]`、`【此处填写】` 这类没填的占位 | 提醒作者补上 |
| Markdown 符号露在纯文本里（`**`、`##` 出现在微信消息里） | 去掉符号 |

## 1. 结构层

| 样子 | 怎么改 | 什么时候留 |
|---|---|---|
| 开场铺时代背景：“在当今……的时代”“随着……的飞速发展”“在这样的背景下” | 删掉，第一句就说事；背景真有用就写那件具体的事 | 背景本身是后文的条件（“上周 MySQL 升级后，……”） |
| 复述问题、预告结构：“这是一个好问题”“下面我将从三个方面为你分析”“本文将深入探讨” | 删掉，直接给内容 | 长文导读需要交代结构，用一句“这篇讲 A、B、C” |
| 结尾总结和升华：“总而言之”“综上所述”“由此可见”“这才是真正的……” | 前文已经说清就删；结论要留就直接写结论 | 论文的结论段、很长的报告末尾的小结 |
| 结尾祝愿和口号：“愿你我都能……”“让我们携手共进，共创……”“未来可期” | 删掉；要表态就写具体打算 | 致辞末尾的一句祝福（“祝大家新年快乐”） |
| 结尾推销：“希望对你有所帮助”“如有任何问题欢迎随时问我” | 删掉 | 客服回复里一句“有问题可以再找我们”，写清找谁 |
| 凑数：硬凑三点、每段都“首先、其次、最后” | 有几点写几点；顺序不重要就不用序数词。不要为了打破“三连”删掉一个独立的例子或事项 | 操作步骤、确有先后的做法 |
| 排版过度：短消息加标题、加粗、列表、表情、分割线 | 消息和邮件写成段落；只留真正要扫读的列表 | 文档、清单、周报里的分点 |
| 同一件事说三遍：开头说、中间说、结尾再说 | 留信息最全的那一遍 | 有意的强调（演讲里的重复） |

## 2. 结构排比

AI 特别爱写有编号感、对仗感的内容，看着条理清楚，读着像打印出来的。数量和对仗本身只是形式，拿它们给内容贴标签，就是排比病。

**显性的一族**

| 样子 | 例子 | 改法 |
|---|---|---|
| 量词标题、量词标签 | “三板斧”“五个维度”“第一刀、第二刀”“N 步走” | 删掉数量，每个小标题写成一句立得住的话 |
| 机械章节编号（文章里） | “一、二、三、四”“第一节”“其一、其二” | 删编号；PRD、技术方案、操作步骤这类查阅用的文档除外 |
| 分号或破折号串起三个以上子句 | “提效；降本；增收” | 留最要紧的一个，或写成一句完整的话 |

**隐性的一族（更容易漏）**

| 样子 | 例子 | 改法 |
|---|---|---|
| “X 不 X”三连以上 | “不急、不躁、不慌” | 留一个，或改成具体的做法 |
| “不是 X 而是 Y”的变体 | “这不是 X”“不在 A，而在 B”“A 不是病，B 才是”“管的是 A，不管 B”“你以为 X，其实 Y”“看似 X，实则 Y”“回头才发现”“真正 X 的是 Y”“A 不重要，重要的是 B” | 全文最多两处。直接说 Y；X 前文说过就删 X；确实要对比，先说成立的，再说不成立的 |
| 一段里两处以上的对仗句 | “就该 A，就该 B”“不必 A，更不必 B” | 留一处，其余正常说 |
| 段内凑满三个的名词或动词串 | “沉淀经验、复盘问题、赋能团队” | 说清具体做了哪件事 |

**统一判据**：盖住这几个并列项，只留一个最要紧的判断，读者的理解会不会少？不会，就是排比病，删掉或改成陈述句；会，就是有效的并列，保留，节奏上补一处停顿。拆的时候每一项的意思都要留下，可以合成一句，不能只留一项。

**例外**：标语、寄语、颁奖词这类要气势的场合，适度的排比和四字句是正当手段，判据照旧。

## 3. 句式层

| 样子 | 怎么改 | 什么时候留 |
|---|---|---|
| “不是 A，而是 B”“A 不等于 B，C 不等于 D” | 多数直接说 B；一段里出现两次以上一定要拆 | A 和 B 是两件不同的具体事实，比如“不是网络问题，是证书过期了” |
| “不仅……更是……”“这不仅仅是一款……更是……” | 两边都在拔高同一件事时，删掉拔高的那边 | 两边各有信息、确有递进 |
| “真正的 X，从来不是……而是……”“才是最高级的……” | 直接说判断，别先立一个靶子 | 引用别人的话 |
| 自问自答：“为什么……？答案其实很简单：” | 直接说观点 | 文章标题本身是问题；用户要求保留设问 |
| “这个故事告诉我们：” | 删掉，让故事自己说话，或用一句平实的感想 | 寓言、教案 |
| “与其说……不如说……”“换句话说”“简而言之” | 说一遍就够 | 真的在换一个角度解释难懂的概念 |
| 空壳动词：“进行了……的调整”“对……进行优化”“实现了……的提升”“起到了……的作用”，以及“作出、完成、存在、具有、属于、构成、导致”当主动词 | 让动词回来：“调整了”“优化……”“提高了”“能……” | 公文里固定的“开展……检查” |
| 句长一样：每句二三十字、句句四平八稳 | 长短搭配；该一句话说完的就一句话 | —— |
| 憋气句：一口气读到底，中途没处停 | 先补逗号断开；别急着拆，更别改成大白话 | 长句本身不是病，有停顿就行 |
| 车轱辘话：相邻两句各说半句同一个意思 | 并句检验：把相邻几句并成一句，信息没少就并掉；少了就是并列或递进，留着。别用“删掉一句读着通不通”来判断，两句凑一个意思时单看每句都正常 | —— |
| “铺垫、展开、小结”三段式 | 一句能说清的判断直接说 | 长文的章节导读 |
| 空过渡句：“顺着这个思路”“说到这里”“接下来我们来看” | 删 | 面向外行的科普讲解里，“那么、于是、但是、所以”是逻辑链，别删 |
| 三连排比：“是……是……是……”“我们……我们……我们……” | 留一个最具体的，或改成一句平实的话 | 演讲里有意的排比，一次就够 |
| 四字格连用：“高效便捷、安全可靠、灵活多样” | 拆开，写具体好处 | 成语本身是作者的用词习惯，零星出现 |

## 4. 词汇层

### 黑话

| 词 | 改法 | 什么时候留 |
|---|---|---|
| 赋能、助力 | 写清谁帮谁做成什么；说不出来就删修饰 | —— |
| 打造、搭建（抽象对象） | 做、建、推出 | 实物（打造一张桌子） |
| 抓手、组合拳、打法、方法论 | 写具体方法 | —— |
| 闭环 | 写清做完了什么、谁跟进 | 闭环控制、闭环反馈 |
| 沉淀 | 记下来、整理成、积累 | 化学、水处理 |
| 对齐、拉齐、拉通 | 统一、确认、说好、打通 | 模型对齐、文本对齐 |
| 颗粒度 | 细到什么程度 | —— |
| 底层逻辑、顶层设计 | 原因、原理、整体规划 | —— |
| 链路、全链路 | 流程、每个环节 | 链路追踪、网络链路 |
| 落地 | 上线、用起来、实施 | —— |
| 深耕、发力、聚焦 | 写具体做了什么 | —— |
| 心智、触达、痛点、赛道、生态、势能、护城河 | 印象、联系到、问题、领域…… | 心理学、生态学、体育的本义 |
| 一站式、全方位、全场景、多维度、无缝 | 列出具体覆盖了什么，或删 | —— |
| 以……为导向、以……为抓手 | 删掉，直接说做法 | —— |

### 夸饰

重磅、全新、重新定义、颠覆、革命性、极致、完美、卓越、惊艳、前所未有、引领、开启新篇章、匠心、保驾护航。

- 改法：删掉，或降成平常说法（“极致流畅”→“很流畅”）。热情用具体好处撑。
- 留：可核查的声明（“行业首个”“比上一版省电 20%”）、承诺（“无需改代码”）、被引用或被讨论的宣传语。

### 空泛拔高

至关重要、举足轻重、不可或缺、扮演着重要角色、具有重要意义、深刻影响、取得显著成效、奠定坚实基础、任重而道远、砥砺前行。

- 改法：说清为什么重要、具体影响了什么；说不清就删。
- 留：作者论证里真正的判断（“散热设计对轻薄本至关重要”是观点，不是渲染）；统计学的“显著”。

### 修饰词

深度、全面、有效、成功、显著、高度、精准、充分、进一步。

- 没有信息就删：“成功上线了”→“上线了”，“全面完成了压测”→“完成了压测”。
- 有信息就留：“部分完成”与“全面完成”的区别要保住。

### 元话语

值得深思、值得关注、值得玩味、值得注意的是、值得一提的是、不难看出、不禁让人思考、引人深思、发人深省。

- 改法：删掉，或换成具体的判断。这些话拿来抬调子，没有给信息。
- 留：后面确实是风险或例外时，“值得注意的是”可以改成“要注意”。

## 5. 翻译腔与欧化

**欧化不必一律洗掉。** “她”“它”的分工、“与其说……不如说”这类早已融进中文的说法留着。要动的是中文本来说得清、偏要套一层英文架子的句子。尺子：中文顺着自己的习惯能说得一样准、一样有劲，就别欧化；中文实在说不清，才借英文的骨架。

**回译试法。** 拿不准时默读，在心里翻回英文：一次成型、一个词一个词对得上的，多半是翻译腔。单个词也一样，“死线”翻回去正好是 deadline，中文有“截止时间”，就换掉；“软件”“进程”“指针”这类早已归化的通用词和标准术语不动。

| 样子 | 改法 |
|---|---|
| “希望这封邮件找到您一切安好”“我写这封邮件的目的是” | 删掉，直接说事 |
| “作为一名开发者，你可能会发现……” | 删掉身份前缀，直接说 |
| “一个非常耗费时间的过程” | “很花时间” |
| “当你在给出反馈的时候” | “给反馈时” |
| “通过遵循……你可以使得……变得更加……” | “照着……做，……会快很多” |
| “被广泛认为”“得到了提升” | 主动说：“大家都认为”“提高了” |
| “关于……的问题”“对于……来说”“在……方面” | 多数可删 |
| 代词过多（“它”“他们”“你的”）、“一个”过多 | 中文能省就省 |
| “然而”“因此”“从而”“此外”密度高 | 留真正转折、因果处的，其余删 |
| 长定语：“采用新教学方法的实验班在课后作业完成质量上……” | 学术文本可留；其他场合拆成两句 |

## 6. 语气姿态

### 聊天腔（AI 助手的回答）

- “这是一个非常好的问题！”“你说得很对”“当然可以！”“完全可以理解”——删。
- “以下是……：”“简单来说，”“一句话总结”——多数删。
- “如果你愿意，我可以……”——保留提议本身，改成“需要的话，我可以……”。

### 服务腔（客服、通知）

- “您的满意是我们最大的追求”“高度重视”“竭诚为您服务”“致以最诚挚的歉意”——删。
- 道歉、感谢各说一次，说清楚就够。
- “第一时间”——写具体时间，或删。

### 宣称和讨好

- 宣称：“很多人没搞懂，而我……”“业内都没想明白”“我早就看透了”。删掉，只摆观察、机理和证据，让读者自己得出判断。
- 讨好：“好问题！”“您说得太对了”“这是一个很好的观点”。删干净，有话直接说。
- 两头都要平视：居高临下和一味讨好，都会让前面的干货打折。

### 工程师腔（AI 编程助手写的中文）

AI 模仿工程师口吻，把调试术语用在日常叙述里，读着像在演。注意分清：技术文档里说得出具体机制或定义的，是术语，照用；专业术语一律用原词，不通俗化（重构不是重写，解耦不是“把模块拆开”，横向扩展不是“加机器”）。

| 词 | 改法 | 什么时候留 |
|---|---|---|
| 收敛一下、收口、收窄 | 缩小范围、理一下、收尾 | 数学、算法里的收敛 |
| 兜底 | 设默认值、保底处理 | 系统设计里的兜底策略（fallback） |
| 稳稳接住、兜住、托住 | 恢复正常、处理好了 | —— |
| 落盘、落下去 | 提交、保存、写进 | 存储系统里的写盘 |
| 口径锁死、不会再漂 | 固定下来、防止回归 | 统计口径、时钟漂移 |
| 更硬的排查、捋一遍、这轮 | 更彻底地查、查一遍、这次 | —— |
| 根因、坐实、对上了、揪出来 | 原因、确认、吻合、找出来 | 事故复盘文档里的“根因” |
| 焊死、钉死、咬死、封死 | 固定、定下来 | “把超时写死在代码里”（hardcode）是正常说法 |

还有一种压缩腔：主语和虚词都被省掉，像电报——“已改。测过。没问题。”“一段脚本进去，结果出来。”读者得自己猜谁做了什么、改了哪里。补回主语和必要的虚词（“我改了配置，测过了，没问题”）。

## 7. 文艺腔与网感

### 文艺腔（游记、随笔、朋友圈）

岁月静好、仿佛置身仙境、宛如一幅画卷、时光在这里慢了下来、治愈了所有疲惫、灵魂得到了洗礼、让人不禁感叹、人间值得、愿你被世界温柔相待。

- 改法：写看到的东西和真实的感受，用平常的字；比喻最多留一个最准的。
- 不要替作者加细节。

### 网感硬凹（小红书、种草）

家人们谁懂、绝绝子、yyds、狠狠心动、氛围感拉满、好用到哭、宝藏好物、闭眼入、冲鸭、每行一个表情。

- 改法：留平台的轻松口吻，但用具体描述代替形容词连发；表情留几个起标记作用的（📍地址）。
- 用户要求保留平台语气时，偶尔一个“绝了”可以留，别句句都是。

## 8. 造词、比喻、词不配位

### 造词

有现成的词就用现成的。AI 爱为了显得凝练自造新词，看着深刻，读者一脸懵。

- 一稿最多一个自造词；用了，就在同一段用大白话解释一次。
- 判断是不是自造：查得到通行的用法吗？同行看到能立刻懂吗？去掉它换成三五个字的大白话，意思少了吗？前两问答“否”、第三问答“没少”，就是自造词，换掉。

### 比喻

比喻只有一个正当用途：拿读者熟悉的东西，讲明白一个读者陌生的概念。

- 比喻比原概念还难懂，删掉，直接说。
- 精确的概念直接说，用不准确的比喻换掉准确的说法，是降低专业性。
- 纯装饰的比喻主动删，别等它碍事。
- 比喻不承担论证。“这就好比……所以……”是拿类比代替推理，回去补机理。
- 合法的比喻也要省，全篇一两个就够。
- 例外：面向外行的科普讲解，比喻是主力，按科普的规矩来。判断读者是同行还是外行。

### 词不配位

动词、形容词要配得上它的对象。随手抓一个听着有力的词，套到它不该形容的东西上，读着别扭，专业的人一眼看穿。

- 先问：这个词本来形容什么？眼前这个对象属不属于那一类？弦会绷，堤会崩；账只会亏空、对不上，不会绷也不会崩。趋势会延续、会逆转，不会塌陷。制度会失灵、会松动，不会生锈。
- 别为了有力牺牲准确。张力靠事实和判断，宁用平实准确的词。
- 判据：把每句的动词、形容词和它的主语拎出来配一遍，问“这个东西真做得出这个动作吗”。做不出来，换。

## 9. 改过头：新长出来的腔调

改稿最常见的失败不是没改干净，而是改出了新腔调。交付前专门看这几样：

- **假口语**：加上“说白了”“讲真”“其实吧”“说实话”“咱就是说”“哈哈”——原文没有就别加。
- **同义换壳**：“赋能”换成“助力”，“闭环”换成“完整链条”，“至关重要”换成“非常关键”——腔调还在。
- **语体漂移**：商务邮件改成聊天，公文改成口语，学术摘要改成科普。
- **磨平观点**：作者明确的判断被改成“或许”“在某种程度上”。
- **加料**：补了原文没有的原因、数字、细节、例子、建议。
- **改丢**：数字、日期、条件、否定、“计划/预计/力争”这类语气词丢了或变了。
- **精度和强度漂移**：“约 42%”变成“超过四成”，“我反对”变成“我持保留态度”，“部分完成”变成“完成”。
- **否定扩大**：“不是网络的问题”只排除了一个原因，不能写成“网络完全正常”；“不能只怪预算不够”不能写成“和预算无关”。
- **过度删减**：为了短删掉了必要的礼貌、过渡和作者的个人表达。
