## 客服机器人接入 LLM：方案摘要

在 AIGC 浪潮席卷各行各业的当下，大模型正以前所未有的速度重塑客户服务行业。本方案不仅是一次技术升级，更是客户服务理念的一次深刻变革，旨在全面赋能客服体验，打造有温度的智能服务，构建智能客服新范式。

**TL;DR**：在现有客服机器人前加一层 LLM 生成回答，知识来源只用已审核的帮助中心文章（约 3800 篇），**不接订单数据**。

**Scope**
- 覆盖：售前咨询、账号问题
- 不做：退款、投诉，直接转人工
- 二期再评估：多轮订单查询

**链路**
query → 意图分类 → RAG（embedding 检索 top-5）→ LLM 生成 → 引用校验。值得一提的是，回答里没有引用时，fallback 到原 FAQ 匹配。

**稳定性**
- SLO：TTFT P99 ≤ 2.5 s
- 对外 SLA 不变，仍为 99.9%
- 降级：LLM 超时超过 8 s，或 5 分钟错误率 > 5%，自动降级到 FAQ 检索

**Rollout**
feature flag `cs.llm_answer`；canary 2% 会话 → 10% → 50%，每档至少 3 天。

**成功标准**
- 转人工率：41% → 35% 以下
- “答非所问”差评占全部差评的比例：不高于现状（6.2%）

**成本**
token 成本预估每月约 4.5 万元（按日均 12 万会话、每会话 1.8 次调用估算）。预算 TBD，待财务确认。

**需要评审会决定**
1. 是否允许把用户最近一单的订单号传给模型？法务意见尚未出。
2. on-call 归属：客服平台组还是算法组？

相信在各方的共同努力下，智能客服必将迎来全新的发展阶段，为用户带来更加极致的服务体验。
