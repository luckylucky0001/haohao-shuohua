## 1. 背景与目标

### 1.1 背景

在移动互联网流量红利见顶的大背景下，消息触达早已不仅仅是一个技术通道，**更是连接用户与业务的核心生命线**。然而，当前我们的推送能力呈现出明显的“烟囱式”特征：订单、营销、社区、IM 四条业务线各自对接厂商推送通道（APNs、华为、小米、OPPO、vivo），全公司共存在 5 套接入代码。每当厂商通道发生升级，同样的改动需要被重复实施 4 遍，仅今年厂商侧接口变更就多达 7 次。

值得注意的是，各业务线的送达率口径也并不一致：订单线按“厂商接口返回成功”计算，营销线则按“客户端到达回执”计算，两边数字的差距最大可达 18 个百分点，导致数据无法横向比较。

因此，我们亟需打造一个**全链路、一站式的统一触达底座**，深度融合各业务线的推送诉求，赋能业务实现极致的触达体验。

### 1.2 目标

本期将建设统一推送网关，四条业务线通过同一套 API 接入，具体目标如下：

- **统一口径**：统一各方认知口径，形成合力。送达率 = 客户端到达回执数 / 有效设备推送请求数，分母剔除已卸载、已关闭通知权限的设备；
- **高性能**：入口峰值支持 2 万 QPS，从网关受理到厂商接口返回 P99 ≤ 5 秒，显著提升推送效率；
- **高可用**：可用性达到 99.95%（按月统计）；
- **全面收口**：Q1 末前四条业务线全部迁入，旧接入代码下线。

### 1.3 非目标

- 不做短信、邮件通道；
- 不做消息内容审核，仍由各业务方自行调用内容安全接口；
- 不改客户端 SDK，是否统一 SDK 二期再评估。

综上所述，统一推送网关的建设将从根本上解决推送能力碎片化的问题，为公司消息触达体系的长期演进奠定坚实基础。
