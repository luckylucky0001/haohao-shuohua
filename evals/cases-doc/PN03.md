# ADR-014：monorepo 用 pnpm workspace + Turborepo，不上 Nx

**Status**：Accepted，2026-10-15

## Context

现在 12 个前端包，yarn v1 + lerna。CI 每次全量 build，约 18 分钟。lerna 基本没人维护了，得换。

评估了 Nx 和 Turborepo：

- Nx 功能更全，但 generator、project.json 要整套接入，迁移成本估 3 人周。
- Turborepo 只加一个 turbo.json，原有 package.json scripts 不用动。

## Decision

用 pnpm workspace + Turborepo。remote cache 先放自建的 S3 兼容存储，不用 Vercel 托管。

PoC：命中 cache 时 CI 约 4 分钟；cold build 和原来差不多。

## Consequences

- 业务包结构不用改，cache 命中时 CI 明显快。
- 没有 Nx 那种 affected graph 可视化，依赖关系出问题要自己查。
- pnpm strict hoisting 会让几个包暴露 phantom dependency，要逐个补依赖。

## Open

- remote cache 清理策略还没定，先手动清。@zhouyi 跟进。
- 包数量到 30 个以上，或者需要代码生成，再看 Nx。
