# 会议室预订冲突提醒 · PRD

负责人：林晓 ｜ 更新：10-21 ｜ 状态：待评审

## 问题

现在两个人可以订同一间会议室的重叠时段，系统不拦也不提醒。9 月行政收到 31 起会议室撞车投诉，22 起是重叠预订造成的，剩下的是有人占着没订。

## 本期做什么

订会议室时，如果和已有预订时间重叠，当场提示，并给出同时段空闲的其他会议室。

## 需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| 1 | 选好时段后，若与已有预订重叠，提交按钮置灰，显示“该时段已被 {预订人} 预订（{开始}–{结束}）” | P0 |
| 2 | 冲突提示下方列出同楼层、容量不小于原会议室的空闲会议室，最多 3 个 | P0 |
| 3 | 创建循环会议时逐次检查，有一次冲突就列出冲突日期，可选择跳过这些日期后提交 | P1 |
| 4 | 在冲突提示里一键给对方发工作消息 | P2，人力不够就砍 |

## 不做

- 会议室占用的自动释放（签到超时释放），另立需求。
- 审批流程不改。

## 验收标准

- 重叠判断：新预订开始时间 < 已有预订结束时间，且新预订结束时间 > 已有预订开始时间。首尾相接（如 10:00 结束、10:00 开始）不算冲突。
- 冲突检查接口 P99 ≤ 200ms。
- 推荐列表为空时显示“同楼层暂无空闲会议室”，不显示空列表。

## 待定

- 跨楼层推荐要不要做，等行政给了楼层间距离的数据再定。
