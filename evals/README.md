# 评测方法

## 测什么

一个去 AI 味的 skill 要同时做到四件事，缺一件都不能用：

1. **改得掉**：腔调重的稿子，改完读不出 AI 味。
2. **不改错**：数字、日期、承诺、条件、否定、语气强弱都不能丢、不能变，也不能编。
3. **不改过头**：本来就自然的文字原样返回；语体不漂（正式的不变成聊天，口语的不变成公文）；不长出新腔调。
4. **自己写得好**：替用户从零写中文时，一开始就写成人话。

`cases/` 下 72 条。前 22 条在任何方案跑分之前冻结（git 历史第一笔提交）；后 50 条在第七轮之前、任何方案跑这批题之前提交（9ceb45f）：

## 流程

1. **出任务单**：`hheval inputs` 只导出用户请求和原文，评分要点不给改写模型看。
2. **改写**：每个方案由一个独立的子代理（Claude Sonnet）执行，读对应 skill 后逐题完成；“baseline”是不加载任何 skill、只按用户原话去做。
3. **盲评**：`hheval blind` 把同一题的各方案输出打乱成匿名的 A/B/C/D/E，映射另存；判官（Claude Opus，与改写模型不同）按 [judge-prompt.md](judge-prompt.md) 逐题打分并排名。
4. **汇总**：`hheval report` 合并判官结果和检查器指标（输出腔调指数、残留、新增腔调、保护项丢失/新增、对照组改动率）。

## 指标

- **保真**：pass / minor / fail，判官对照“必须保留的信息”逐条核对。
- **去味、自然、语体**：1–5 分；三项平均为“质量分”。
- **名次与胜率**：每题严格排名；名次 0 表示总排第一；胜率是两两比较中排在对方前面的比例。排名时保真优先。
- **过度修改**：只对对照组打 0–2 分。
- **检查器指标**：只作参考，判官的判断优先。

## 局限

- 判官和改写都是模型，不等于人类编辑的共识；判官与本项目作者同属一个模型家族，可能有偏好。样本小：第五、六轮实测，同一个 skill 重新采样一次胜率能差 8 个百分点，同一份输出重新判分能差 5 个点左右，所以 5–8 个点以内的差别不能当真，名次差异要结合逐题记录看。
- 上游项目（说人话、Humanizer-zh、qu-ai-wei）按各自的 SKILL.md 运行；它们主要为改稿设计，所以只参加改稿和对照题。
- 第三轮以后，v0.1 和不装 skill 的输出在相邻几轮之间复用（只重新判分）；第五轮起 v0.1 另做了一次重新采样，记作 haohao-v0.1b。第六轮 v0.4.2 第二次采样的 W04 说明文件在打包后才写完，判官看到的是没有说明的版本。
- 第七轮新增的 50 条用例由子代理起草（只能看旧用例做格式参考，不能看 SKILL.md），起草和判分的模型与改写模型同属一个家族。旧 22 题在第七轮沿用第五、六轮的输出，只重新判分。
- 用例由本项目作者编写，可能偏向本项目在意的问题。
- **同一份输出换一批判官，结果能差不少**：第十二、十三轮里 v0.6.3 和 v0.5.1 用的是完全相同的输出，只是和不同的第三个方案放在一起重新判分，逐题从 35 比 37 变成 27 比 45；H5、H6 里 v0.6.3 和 v0.7 的输出也相同，胜率从 65% 对 71% 变成 48% 对 50%。所以单轮 10 个点以内的差距，以及只出现一次的显著性，都不要当真。
- **留出集用过多次**：`cases-doc-holdout/` 的 12 题在 H1–H4 都用过，v0.6.3 的两处改动参考过 H3 的判官意见，所以 H4 只能算半个留出。第九轮有一个改写子代理读了输出目录里别的方案的文件，那一轮 v0.6 的个别输出可能受了影响。
- 第十一、十二轮里，v0.5.1、v0.6、v0.6.2 的输出沿用上一轮的采样，只重新判分；第十一轮 W01 的输出里有一处人名和用例不一致，统一后单独重判了那一包。
- **v0.1 有泄题**：v0.1 的 SKILL.md 和参考资料里有几处示例直接取自用例（R01 的告警分级、R04 的两句金句、N01 的口语、R08 的否定句），规则表里“紧紧围绕”“华丽转变”等几条也是看过 R01 后补的。v0.2 起示例全部换成与用例无关的内容；规则表保留这些常见说法，因为它们本身就是真实文本里的高频腔调。
- **用例里有两处日期写错**：R09 的“本周六（10 月 25 日）”和 W01 的“下周三（10 月 29 日）”与 2026 年的日历不符（N04 的两个日期是周六，但不算错）。这不是有意设计，但正好检验“发现事实疑点时是否提醒、是否擅自改”，判分时不因没提醒而判保真失败。

每轮结果在 `results/`（报告、图、判官原始 JSON、逐题简评），原始输出和任务单在 `runs/`，迭代记录在 [../docs/iterations.md](../docs/iterations.md)。

复现：

```bash
go run ./cmd/hheval inputs -kinds rewrite,control -out tasks.md            # 出任务单
# 让各方案（各自加载 skill 的子代理）把输出写到 runs/<轮次>/<方案>/<用例>.md
go run ./cmd/hheval blind -runs runs/<轮次> -conds a,b,c -batches 4 -out judge/<轮次>
# 判官按 judge-prompt.md 把结果写到 judge/<轮次>/result-*.json
go run ./cmd/hheval report -runs runs/<轮次> -judge judge/<轮次> -svg chart.svg -out report.md
```

## 对外版本的处理

用例和各轮输出里出现过的具体协作平台名和个别产品名，统一换成了中性说法（如“工作群”“企业 IM”），一个用作作者名字的英文名换成了“Leo”。替换在用例、输出和判官记录里同步进行，不影响评分结论。
