# ADR-017：Monorepo 包管理器从 yarn v1 迁移到 pnpm

- 状态：已接受（Accepted）
- 评审：2026-10-19，前端架构组评审通过

## 背景

Monorepo 里有 42 个 package，使用 yarn v1 管理依赖。具体情况如下：

- CI 冷启动 install 平均耗时 6 分 40 秒。
- 幽灵依赖（phantom dependency）在上个季度导致了 2 次线上事故。
- yarn v1 已经不再新增功能。

## 决策

迁移到 pnpm 9，使用 pnpm workspace。`node-linker` 保持默认的 `isolated`，不开启 `shamefully-hoist`。

Node 版本升级不在本 ADR 范围内，另起一份。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| yarn berry（PnP） | 不选 | PnP 与现有 Jest 配置和一部分 webpack 插件不兼容，需要逐个修改，工作量目前评估不出来 |
| npm workspaces | 不选 | 解决不了幽灵依赖 |

## 后果

### 好处

- CI install 耗时预计降到 2 分钟以内。这个数字来自 3 个 package 的试点，全量 monorepo 还没有验证。
- 磁盘占用下降。

### 代价

- 有 7 个 package 存在隐式依赖，需要补上 `dependencies` 声明。
- 本地开发需要先运行 `corepack enable` 来安装 pnpm。
- 需要修改 Renovate 配置。
- 迁移当周冻结 `package.json` 的改动，避免 lockfile 冲突。
