## 客服 Reply Draft 项目：方案摘要

### 需要你拍板的两件事

1. Pilot 预算批不批：按每月 $9k 上限。
2. EU 客户的工单要不要纳入 pilot：法务意见还没回，我们倾向先排除。

### 做什么

给一线客服生成 reply draft，agent 人工确认后才发送，不做 auto-send。

### 怎么做

- 架构是 RAG：Help Center 大约 3,800 篇文章做 embedding，存进 vector DB。
- LLM 调用统一走公司的 LLM Gateway。

### Pilot 范围

先在 EN queue 做，约 25 个 agents，跑 4 周。

### 成功指标

- AHT 目标降 15%。
- draft adoption rate（直接使用或小改后发出的 draft 占比）≥ 40%。
- CSAT 不能降。

### 成本与排期

- Token 成本：按现在的工单量估算，每月大概 $6k–9k。这是估算，还没算 embedding 重建的费用。
- 开发预计 3 周，前提是 LLM Gateway 的配额能开下来。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| Hallucination：模型可能编错 refund policy | 凡是涉及 refund / compensation 的 intent，只给知识库原文链接，不生成任何承诺性的话 |
| PII | 调 LLM 前先做 PII masking，邮箱、手机号、订单号都打码 |
| 延迟 | P95 目标 < 5s；超时就不展示 draft，不阻塞 agent |

### 不在这次范围

中文 queue、auto-send、语音工单。
