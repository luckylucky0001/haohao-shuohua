## 1. 背景与目标

### 1.1 背景

当前我们的推送能力是“烟囱式”的：订单、营销、社区、IM 四条业务线各自对接厂商推送通道（APNs、华为、小米、OPPO、vivo），全公司共存在 5 套接入代码。每当厂商通道发生升级，同样的改动需要被重复实施 4 遍，仅今年厂商侧接口变更就多达 7 次。

各业务线的送达率口径也不一致：订单线按“厂商接口返回成功”计算，营销线则按“客户端到达回执”计算，两边数字的差距最大可达 18 个百分点，导致数据无法横向比较。

### 1.2 目标

本期将建设统一推送网关，四条业务线通过同一套 API 接入，具体目标如下：

- **统一口径**：送达率 = 客户端到达回执数 / 有效设备推送请求数，分母剔除已卸载、已关闭通知权限的设备；
- **高性能**：入口峰值支持 2 万 QPS，从网关受理到厂商接口返回 P99 ≤ 5 秒；
- **高可用**：可用性达到 99.95%（按月统计）；
- **迁移**：Q1 末前四条业务线全部迁入，旧接入代码下线。

### 1.3 非目标

- 不做短信、邮件通道；
- 不做消息内容审核，仍由各业务方自行调用内容安全接口；
- 不改客户端 SDK，是否统一 SDK 二期再评估。
