# ADR-017：monorepo 包管理器从 yarn v1 迁移到 pnpm 9

- 状态：已接受（Accepted）
- 日期：2026-10-19（前端架构组评审通过）

## 背景

monorepo 目前有 42 个 package，使用 yarn v1 管理依赖。现状存在以下问题：

- CI 冷启动 install 平均耗时 6 分 40 秒。
- 幽灵依赖（phantom dependency）在上个季度导致了 2 次线上事故。
- yarn v1 已不再增加新功能。

## 决策

迁移到 pnpm 9，使用 pnpm workspace。

- node-linker 保持默认的 isolated。
- 不开启 shamefully-hoist。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| yarn berry（PnP） | 不选 | PnP 与现有 Jest 配置、部分 webpack 插件不兼容，需要逐个改造，工作量无法评估 |
| npm workspaces | 不选 | 解决不了幽灵依赖 |

## 后果

### 收益

- CI install 耗时预计降到 2 分钟以内。注意：该数据来自 3 个 package 的试点，全量 42 个 package 尚未验证。
- 磁盘占用下降。
- 依赖按 isolated 方式链接，包只能访问自己声明的依赖，用于杜绝幽灵依赖。

### 代价

- 有 7 个 package 存在隐式依赖，需要补全 dependencies 声明。
- 本地开发需要先执行 `corepack enable` 来安装 pnpm。
- Renovate 配置需要修改。
- 迁移当周冻结 package.json 的改动，避免 lockfile 冲突。

## 范围说明

Node 版本升级不属于本 ADR，另起一份记录。
