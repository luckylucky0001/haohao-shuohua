## 灰度与回滚

### 1. 灰度机制

- 分流方式：按 user_id 哈希分流。
- 开关：feature flag `eta_model_v3_enabled`。
- 对照组：未放量的流量继续使用旧模型，用于和 v3 对比。

### 2. 放量节奏

| 阶段 | 流量比例 | 观察时长 |
|---|---|---|
| 1 | 5% | 2 天 |
| 2 | 20% | 3 天 |
| 3 | 50% | 3 天 |
| 4 | 100% | 全量 |

每次放量（进入下一阶段）前，必须由算法负责人和当班 SRE 两人都确认后才能执行，缺一不可。

### 3. 观察指标

| 指标 | 要求 | 说明 |
|---|---|---|
| ETA 平均绝对误差（MAE） | ≤ 4.5 分钟 | 旧模型现网约 6.2 分钟 |
| 超时订单率 | 不高于对照组 | 超时订单率 = 实际送达晚于预估时间的订单占比 |
| 预估接口 P99 | ≤ 80ms | |
| 用户催单进线率 | 仅观察 | 受天气影响大，不作为回滚条件 |

### 4. 回滚条件

以下任意一条触发，立即回滚：

1. 预估接口 P99 > 120ms，且持续 10 分钟。
2. 接口错误率 > 0.5%。
3. 超时订单率比对照组高 1 个百分点以上。

### 5. 回滚操作

1. 关闭 feature flag `eta_model_v3_enabled`，1 分钟内生效，无需发版。
2. v2 模型服务保留到 v3 全量后 2 周再下线，在此之前随时可回切。

### 6. 兜底（降级）

模型服务调用超时 50ms 时，降级为原来的规则公式计算 ETA。
