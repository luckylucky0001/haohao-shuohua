## 做什么

给一线客服生成 reply draft，agent 人工确认后才发送，不做 auto-send。

- 架构：RAG。Help Center 约 3,800 篇文章做 embedding 进 vector DB，LLM 调用统一走公司的 LLM Gateway。
- Pilot：先在 EN queue，约 25 个 agents，跑 4 周。
- 开发：预计 3 周。前提是 LLM Gateway 的配额能开下来。

## 成功指标

| 指标 | 目标 |
|---|---|
| AHT | 降低 15% |
| Draft adoption rate（直接使用或小改后发出的比例） | ≥ 40% |
| CSAT | 不下降 |

## 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| Hallucination：模型可能编造错误的 refund policy | 凡涉及 refund / compensation 的 intent，只给知识库原文链接，不生成任何承诺性内容 |
| PII | 调用 LLM 前先做 PII masking，邮箱、手机号、订单号都打码 |
| 延迟 | P95 目标 < 5s；超时则不展示 draft，不阻塞 agent |

## 不在本次范围

中文 queue、auto-send、语音工单。
