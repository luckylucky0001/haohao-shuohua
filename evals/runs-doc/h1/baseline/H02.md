## 4. 功能需求与优先级

本期举报处理后台按“受理—分派—处置—回访”四个环节组织，需求如下：

| 编号 | 功能模块 | 需求描述 | 优先级 |
|---|---|---|---|
| F1 | 举报工单队列 | 按举报类型（`spam` / `porn` / `abuse` / `ip_infringe` / `other`）分队列展示，支持按被举报次数、首次举报时间排序 | P0 |
| F2 | 自动分派 | 按队列轮询给审核员分派工单，单人同时持有的待处理工单不超过 20 张 | P0 |
| F3 | 处置操作 | 支持删除内容、折叠、限流、禁言 1/3/7 天；封号必须二次确认，且仅 L2 及以上审核员可操作 | P0 |
| F4 | 批量处置 | 同一被举报内容的多张工单合并处理，一次处置全部关闭 | P1 |
| F5 | 结果通知 | 处置后通过站内信通知举报人处理结果，文案沿用现有模板 `report_result_v2` | P1 |
| F6 | 处置申诉 | 被处置用户可发起申诉，进入独立的申诉队列 | P2，二期再评估 |
| — | 机审预标注 | 不在本期范围 | 不做 |

> 注：F3 中的“限流”指降低该内容的推荐分发权重，不是接口层面的限流。

## 5. 验收标准

各项需求的验收标准如下，每条对应一个可独立验证的检查点。F6、机审预标注不在本期，不列验收标准。

- **F1**
  - 提交一条举报后，≤ 1 分钟内该工单出现在对应举报类型的队列中。
  - 队列中有 5,000 条待处理工单时，队列列表页 P95 加载时间 < 2 秒。
  - 队列列表可按被举报次数、首次举报时间排序。
- **F2**
  - 任一审核员持有的待处理工单数不超过 20 张；持有 20 张时不再向其分派新工单。
  - 审核员状态切为“离开”超过 10 分钟后，其未处理工单自动回收到队列。
- **F3**
  - 每次处置都向操作日志表 `moderation_action_log` 写入一条记录，包含操作人、操作类型、原因码、时间。
  - L1 审核员调用封号接口 `POST /api/moderation/ban`，返回 `403 PERMISSION_DENIED`。
  - L2 及以上审核员封号时必须经过二次确认，未确认则不执行封号。
  - 禁言可选 1 / 3 / 7 天。
- **F4**：对同一被举报内容的多张工单执行一次合并处置后，这些工单的状态全部变为 `closed`。
- **F5**
  - 处置后 5 分钟内，举报人收到站内信，文案使用模板 `report_result_v2`。
  - 站内信发送失败时进入重试，最多重试 3 次。
