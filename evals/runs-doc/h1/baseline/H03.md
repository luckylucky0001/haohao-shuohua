## 4. 方案对比与选型

车源搜索目前基于 Elasticsearch 7.10，只有 BM25 关键词召回，对用户的语义化表达覆盖不足。本节对比四个候选方案，并给出选型结论。

### 4.1 候选方案

- **方案 A**：维持现状，ES 7.10 + BM25 关键词召回；
- **方案 B**：全量迁移到自研向量检索引擎（基于 HNSW）；
- **方案 C**：混合检索，ES 保留关键词召回，同时接入自研向量召回，两路结果用 RRF 融合；
- **方案 D**：将集群升级到 ES 8.x，直接使用其自带的 kNN 检索。

### 4.2 对比数据

离线评测基于 2,000 条人工标注 query：

| 方案 | NDCG@10 | 精确车型类 query Top3 命中率 | 检索 P99 | 机器成本（相对现状） |
|---|---|---|---|---|
| A 现状 | 0.412 | 91% | 85ms | — |
| B 全量向量 | 0.437 | 64% | 60ms | 约 -15% |
| C 混合检索 | 0.468 | 90% | 120ms | 约 +40% |
| D ES 8.x kNN | 未评测 | 未评测 | 未评测 | 未评测 |

### 4.3 分析与结论

方案 B 的 NDCG@10 和 P99 都优于现状，机器成本也约低 15%。但精确车型类 query（如“凯美瑞 2021 款”）占搜索 PV 的 23%，B 在这类 query 上的 Top3 命中率从 91% 降到 64%，这部分流量的损失我们不能接受。

方案 D 需要把集群从 7.10 升级到 8.x，涉及 mapping 和客户端的改造，且 8.x 的 kNN 在我们 3,800 万条车源的规模下表现如何还没有验证，本期不做评估。

方案 C 的 NDCG@10 为 0.468，是已评测方案中最高的；精确车型类 query 的 Top3 命中率为 90%，与现状（91%）基本持平。P99 从现状的 85ms 升到 120ms，仍在 150ms 的延迟预算之内。代价是两套召回都需要维护，机器成本约增加 40%。

**结论：选择方案 C（混合检索）。** 二期为向量召回加上 sparse 向量后，如果精确车型类 query 的 Top3 命中率能达到 ≥ 88%，再评估是否下掉 ES 关键词召回。精排 / 重排模型的调整不在本次方案范围内。
